Training Tab — Complete Adaptive Design

Model declares its metrics. UI renders them. Zero frontend changes to add a new model. Includes 3D loss surface in both phases.

DESIGN PRINCIPLE

Every model emits metric_declarations before training starts. These declarations define what groups exist, what renderers to use, and what order to display them. The Training tab reads these declarations and builds itself. A new model type = a new Python script. No React code touched.

Key Design Decisions

Model declares everything
metric_declarations SSE event defines groups, renderers, ordering. Tabs auto-generated from groups. No hardcoded tabs per model.
Phase-aware layout
During training: split view (live metrics + log) + trajectory. After training: full-width MetricGrid with group tabs + loss surface. Groups awaiting data shown as greyed-out pills.
Zero-touch new models
New model = new Python script emitting metric_declarations + emit_metric(). Training tab auto-renders. No React components, no routing, no adapter changes needed.
3D Loss Surface (new renderer)
Live: trajectory via PCA on weight deltas (cheap, per-epoch). Post: 51x51 grid scan (Li et al. 2018, ~30-60s). New surface_3d renderer in the self-describing system. Three.js/R3F.
12-col grid preserved
Same renderer span system (gauge=3col, time_series=6col, surface_3d=6col, table=12col). MetricGrid scoped to active group tab.
Model Browser (collapsible)
Stays at the bottom — select any trained model to load its saved diagnostics into the same tab/grid layout. Model type auto-detected, tabs re-generated.

New Renderer: surface_3d
