Training Tab — Adaptive Layout Design

The model declares its metrics. The UI renders them. Zero frontend changes to add a new model.

DESIGN PRINCIPLE

Every model emits metric_declarations before training starts. These declarations define what groups exist, what renderers to use, and what order to display them. The Training tab reads these declarations and builds itself. A new model type = a new Python script. No React code touched.

Key Design Decisions

Model declares everything
metric_declarations SSE event defines groups, renderers, ordering. The tabs are auto-generated from these groups. No hardcoded tabs per model.
Phase-aware layout
During training: split view (live metrics + log). After training: full-width MetricGrid with group tabs. Groups with no data yet shown as greyed-out pills.
Zero-touch new models
New model Python script emits metric_declarations + emit_metric(). The Training tab auto-renders. No React components, no routing, no adapter changes needed.
12-col grid preserved
Same renderer span system (gauge=3col, time_series=6col, table=12col). MetricGrid already does this — just scoped to the active group tab now.
