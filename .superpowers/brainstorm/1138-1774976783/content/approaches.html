Agent Workforce Architecture — 3 Approaches

Click the approach that resonates. Each has distinct cost/complexity/capability tradeoffs.

A

Claude Agent SDK Workforce

Every agent is a Claude Agent SDK query() call with custom system prompts and tools. CEO orchestrates via subagents. Built-in file/web/shell tools.

Architecture A — Full Agent SDK

Pros

  • Built-in Read/Write/Bash/Grep/Glob tools
  • MCP server support
  • Permission system included
  • Subagent spawning native

Cons

  • Every agent call = Claude API cost
  • No Ollama support — all Opus/Sonnet
  • $50-200/day for continuous monitoring
  • Requires Claude Code CLI in Docker
B

Custom Python Framework

Build everything from scratch with Anthropic SDK + Ollama. Custom tool definitions, custom routing, full control over which model handles each task.

Pros

  • Ollama for cheap monitoring
  • Full model routing control per task
  • Custom tools per domain
  • ~$5-15/day (mostly Ollama)

Cons

  • Must build all tool infra from scratch
  • No built-in file/shell/web tools
  • More code to write and maintain
  • No Agent SDK permission system
C

Hybrid — Agent SDK CEO + Custom Workers (Recommended)

CEO uses Agent SDK for full Claude intelligence when you give directives. Workers are lightweight Python services using Ollama for monitoring and Claude API (via tool_runner) only when escalating complex decisions.

Architecture C — Hybrid

Pros

  • Best cost/capability ratio (~$5-15/day)
  • Ollama handles 90% of monitoring (free)
  • CEO gets full Agent SDK power on demand
  • Workers escalate to Claude only when needed
  • Clean separation: daemon vs on-demand

Cons

  • Two frameworks (Agent SDK + custom Python)
  • More complex initial setup
  • Need to define escalation boundaries
